> 大家好，非常荣幸收到社区邀请，成为 Apache HertzBeat™ PMC 成员。

距离上一次写[新晋 Committer 的博客](https://hertzbeat.apache.org/blog/2025/10/31/new-committer)，差不多过去了一年。那篇文章的结尾我写道："成为 Committer 意味着肩负更多责任。"这一年，也在尝试着落到实处。

## 这一年的数字

> [139 commits](https://github.com/apache/hertzbeat/commits?author=Duansg)41,285 ++ 11,444 --

累计提交并合并 139 个 PR，改动 1,002 个文件。其中 **88 个 PR 是在成为 Committer 之后完成的**，我的贡献重心悄悄变了——从"修我遇到的 bug、加我需要的功能"，变成了"做那些没人催、但必须有人做的事"。

## 重心的转移

这一年的工作主要集中在四个方面：

- **安全加固**：系统性地梳理接口与权限配置，推动了一批加固改进。
- **发版工程**：参与 1.9.0 的准备与发版，从数据库迁移、许可证物料到升级指南，第一次从"这个版本能不能发"的视角审视项目。
- **工程基础设施**：让原生采集器真正跑起来，完善 CI 与构建流程。
- **告警与稳定性**：持续打磨告警链路，修复内存泄漏与回归问题等。

## 从提交代码，到参与社区

如果说这一年里有哪件事最改变我对开源的理解，那一定是 Review。

到目前为止，我 Review 过社区 **97 个 PR**，参与了 **207 个 Issue 与 PR 的讨论**。这些 PR 来自四十余位贡献者，其中不少是他们的第一次贡献。

去年写博客时我说，Review 时要"给予贡献者建设性的反馈与认可"。真正做下来才发现，最难的不是找出问题，而是把握分寸：什么时候该坚持、什么时候该放行；如何在指出问题的同时，不浇灭一个人第一次提
PR 的热情。我自己也是从第一个被合并的文档 PR 开始的，那种被回应、被认真对待的感觉，依然记得很清楚。

## 成为 PMC 意味着什么

对我来说，PMC 不是一枚更大的徽章，而是关注点的又一次转移：从"我的代码"到"项目的健康"。

- **对用户负责**：关注用户在使用与升级中遇到的问题，让每一个版本都稳定、可靠、升级顺畅。
- **对贡献者负责**：及时 Review、完善文档、降低参与门槛，帮助更多新人成长为长期贡献者。
- **对项目的长期负责**：保持技术判断的诚实，参与长期路线规划与社区治理，让决策更透明、协作更顺畅。

## 给开源开发者的建议

去年我说"开源之路始于兴趣，成长于实践"，今年我想补充一句：**成长于责任。**

对刚起步的开发者，勇于提出第一个 PR 依然是最重要的一步。而当你在一个项目里待得足够久，会自然遇到一个转折点——你开始看见那些"
不属于任何人"的问题：过期的文档、脆弱的 CI、没人核对的依赖清单、无人认领的边界情况。

**去接住其中一个。** 这也是从贡献者走向维护者最自然的一条路，也是社区最需要的那种人。
