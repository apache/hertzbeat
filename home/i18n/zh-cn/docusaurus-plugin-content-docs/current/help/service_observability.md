在 **应用可观测 → 服务**（`/observability/services`）中查看已注册的服务实体及其观测信号。空目录表示没有已注册服务匹配目录过滤条件，不表示没有遥测。没有解析到实体的遥测仍可通过直接 **Explore** 入口，按服务、命名空间、环境和时间查询。

## 排查一个服务

1. 按名称或目录环境过滤列表，选择服务。
2. 选择调查时间范围，点击 **查询**。信号读取使用最多 24 小时的有界绝对时间窗。
3. 查看服务身份、请求 RED、已观测根链路操作和已有关系。
4. 点击操作的 **错误链路**，查看该操作的失败根链路。打开具体链路后，可在存在关联信息时继续查看相关日志。
5. 先 **返回结果**，再 **返回服务**，沿调查路径返回。服务、环境、操作选择、错误过滤和绝对时间窗都会保留。

身份详情、RED、操作和链路观测时间独立加载。某一区域失败不会被替换成零，也不会将服务标记为健康。格式错误的显式时间窗会一直保持无效，直到选择合法预设并点击 **查询**。

## 正确理解证据

| 证据 | 含义与边界 |
|---|---|
| 目录来源 | 实体记录中的来源，不代表当前 OTLP 传输方式 |
| 窗口内最近观测链路 | 当前服务范围和时间窗内的历史 Trace 观测，不是存活保证 |
| 请求 RED | Greptime Flow 对已观测 SERVER span 按 60 秒桶进行的服务级聚合 |
| 已观测根链路操作 | 最多 20 个操作组，按错误链路数量排序；根链路证据，不是完整请求清单 |
| 已有关联 | 当前监控关联告警和最多 50 个已注册关系预览；不是完整推断依赖，也不是调查时间窗的历史快照 |

只有存储与身份支持对应证据时才有 RED。请求速率、错误率和延迟使用已观测的 Flow 数据。分钟桶按桶起始时间选取；未对齐的调查窗会包含选中的完整桶。采样完整性未知，P95 为近似值且可能不可用。缺少延迟不等于零。

选择操作后，RED 仍然是 **服务级** 数据。下游服务可以有 SERVER span 的 RED，但没有根操作组。目录元数据更新时间不会被当成最近 Trace 观测时间。

## 选择合适的信号入口

**打开链路** 使用服务范围和根 span。操作入口还应用精确操作名称，**错误链路** 额外应用错误条件。排序与覆盖范围见 [Explore 与保存查询](./explore_saved_queries.md)。

**打开服务日志** 携带服务范围和绝对时间窗，不会假定日志具备与 Trace API 相同的操作或错误条件。若要查看某个操作对应的日志，应先进入该操作的链路，再沿具体链路的关联日志入口查看。

**打开指标** 携带受支持的服务调查上下文。若上报指标不含请求的标签，合法查询可以返回空。RED 缺失或不受支持，不会让任意 JVM 指标变成请求 RED。

**打开实体证据** 展示已有实体详情和已注册关联。没有关联告警或关系预览，只表示该视图没有相应证据，不代表服务在任何地方都没有告警或依赖。

## 数据缺失与未解析身份

扩大查询范围前，先核对时间、服务命名空间、环境和实例条件。读取失败与权限失败需要分别处理，不能当作空结果。界面区分不可用、空、加载中和失败状态。

资源身份尚未解析时，其日志、指标和链路仍可能可以直接查询。只有命名空间或环境不足以确定服务实体。请使用 **Explore** 查询未解析资源，而不是为了填满目录将其关联到无关实体。
